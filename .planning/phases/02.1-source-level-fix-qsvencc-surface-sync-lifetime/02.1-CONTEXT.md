# Phase 02.1: Source-Level Fix — qsvencc Surface Sync & Lifetime - Context

**Gathered:** 2026-10-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Find, in qsvencc source (tag 8.31, worktree `/workspaces/qsvenc-831`), why 3-way concurrent `--avhw --va` + P010 (`--output-depth 10`) + B-pyramid (`--gop-ref-dist 6 --b-pyramid`) sessions emit a deterministic corrupted frame (~12.8 dB at 923/299 and 1129/299) while ffmpeg `av1_qsv` with the same kernel/driver/triad stays clean — and, if a fix is found, deliver a minimal upstream-ready patch validated by the unmodified Phase-1 harness. Scope is surface **synchronization** and surface **lifetime/reuse** (and, conditionally, per-component allocator pools). Surface-attribute variants (`rt_format`, `VASurfaceAttribUsageHint`) and `--async-depth 1` stay out of scope (already proven inert).

A documented negative result (every examined hypothesis confirmed/refuted with numbers) is an acceptable phase outcome.

</domain>

<decisions>
## Implementation Decisions

### Investigation strategy
- **D-01:** **Offline mechanism check first (no GPU).** Before any instrumentation, analyze the already-saved corrupt outputs in `scratch/repro-831/runs/it*/` (and `scratch/repro/runs/`): compute PSNR of each corrupt frame against **all** frames of its own scene's clean reference encode (not just ±5) and against the decoded **source input** frames of that scene. Goal: decide whether the corrupt frame is stale/mixed content from its **own** session (intra-session surface reuse) vs. something else. Phase 2 already showed 0/17 are cross-session whole-frame swaps — this result chooses where to instrument.
- **D-02:** **Primary method = instrumentation of qsvencc**, not blind patching. Add a lightweight trace of the surface path decode → VPP (nv12→p010) → encode: per frame record VASurfaceID / `mfxFrameSurface1*`, `Locked` count at hand-off and at reuse (`PipelineTaskSurfaces::getFreeSurf`, `qsv_pipeline_ctrl.h:238`), syncpoint presence and whether `SyncOperation` (`qsv_pipeline_ctrl.h:352`) completed before the surface was consumed or returned to the pool. Correlate a corrupt run's trace with the corrupt frame index.
- **D-03:** **Trace must not mask the race.** In-memory buffered log, enabled by env var, flushed at exit — no per-frame stdio. Mandatory gate: the instrumented build must still reproduce at a comparable rate (N=20, vs 8.31 baseline 30–45 %) before its traces are trusted. If instrumentation makes the bug disappear, record that as a timing signal (itself evidence for a sync race) and fall back to D-05.
- **D-04:** **Targeted static comparison with ffmpeg, in parallel (research phase).** Compare qsvencc vs ffmpeg (`libavcodec/qsvdec.c`, `qsvenc.c`, `libavfilter/vf_vpp_qsv.c` / `qsvvpp.c`, `libavutil/hwcontext_qsv.c`) only along the three hypothesis axes: (1) when a surface is handed downstream vs `SyncOperation` completion, (2) surface reuse rules / `Locked` handling / pool sizing, (3) external allocator & pool topology (single OR-combined `FROM_DECODE|FROM_VPPIN|FROM_ENCODE` pool vs per-component `AVHWFramesContext`). Output feeds instrumentation points — not a standalone full line-by-line audit.

### Diagnostic patches
- **D-05:** **Coarse localizing patches only if the trace is inconclusive.** If trace pinpoints the site → go straight to a targeted patch. Otherwise bisect with coarse patches, one boundary at a time: forced sync at decode→VPP, forced sync at VPP→encode, quarantine (delayed reuse) of freed surfaces / enlarged pool.
- **D-06:** **Allocator restructuring (hypothesis 3: split the shared VA pool into per-component pools, ffmpeg-style) only after hypotheses 1 and 2 are refuted.** Costly change; treated as a diagnostic experiment, not a first move.
- **D-07:** **Throughput cost is acceptable** for a fix that passes validation (Core Value: correctness first). Record fps of patched build vs stock 8.31 (and note the `--avsw` workaround for Phase 4 comparison).

### Budget & stop rules
- **D-08:** Per candidate: detection batch N=20 through the unmodified harness (copy in `scratch/repro-831/`, paired ffmpeg `av1_qsv` control). **≥1 corrupt frame on 923/299 or 1129/299 = not a fix** (a lowered rate is logged as a diagnostic signal only). **0/20 with clean control → immediately escalate to ~60 zero-failure iterations** (rule-of-three) plus single-session bit-exactness re-check (determinism md5).
- **D-09:** **Phase budget by candidate count:** stop when hypotheses 1–3 plus coarse patches are exhausted without localization (≈ ≤10 detection batches of N=20). Beyond that — escalate to operator, don't keep spinning.
- **D-10:** **Negative result is a valid close.** Deliverable `02.1-EVIDENCE.md`: per hypothesis — confirmed/refuted, the numbers, what the trace showed. This also feeds the upstream issue draft and Phase 3.

### Fix form & upstream
- **D-11:** **Minimal, upstream-ready fix**: commit(s) on a branch off tag `8.31` in `/workspaces/qsvenc-831`, matching surrounding code style; respect common-file rules (`rgy_*` shared across QSVEnc/NVEnc/VCEEnc/rkmppenc — use `ENCODER_QSV` macros if a shared file must change; prefer QSV-specific files). Export as `.patch`. Diagnostic tracing lives in a **separate commit**, not in the fix.
- **D-12:** **Fix is always-on, no new CLI option.** A correctness fix must not be opt-in; if its cost is high, scope it by condition (VA memory / `--avhw` path) rather than a flag. Consequently no `qsv_prm`/`qsv_cmd`/`QSVEncC_Options.*.md` changes are expected.
- **D-13:** **Upstream: update draft only.** Update `qsvenc-upstream-issue.md` with mechanism, patch and numbers. Publishing an issue / PR / comment on rigaya/QSVEnc #308 happens only on explicit operator decision — not within this phase.
- **D-14:** Requirement for ROADMAP/REQUIREMENTS (to be added at plan time): **FIX-01** — "Each examined surface-sync/lifetime/allocator hypothesis is confirmed or refuted by harness measurement; any claimed fix passes ~60 zero-failure 3-way iterations on 923/1129 with control 0/N and preserved single-session bit-exactness."

### Carried forward (not re-decided)
- Unmodified Phase-1 harness; `<30 dB` = corrupt; external-ffmpeg PSNR (OpenCL-free); paired `av1_qsv` control per batch, non-zero control invalidates the batch.
- Build in `/workspaces/qsvenc-831`; harness copy & outputs in `scratch/repro-831/` (Phase-1 `scratch/repro/` untouched); run on main tree, **worktree isolation OFF** for any `scratch/`-producing plan.
- Sequential GPU usage — no concurrent experiments on the A380.
- Never write to `/data`.

### Claude's Discretion

- Concrete instrumentation sites beyond those named in D-02.
- Which coarse patch to try first in D-05 (guided by D-01/D-04 findings).
- How patched binaries are put on the harness's PATH (e.g. `scratch/repro-831/bin`) and how per-candidate results are named/archived so batches don't overwrite each other.

<code_context>
## Existing Code Insights

### Reusable Assets
- Phase-1 harness (`probe` → `reference` → `run-batch N`) with paired control and Wilson-CI summary — reused unmodified for every candidate.
- Phase-2 content cross-match tooling (`scratch/repro/crossmatch_*`) — base for the D-01 offline intra-session analysis.
- 8.31 build toolchain already validated in `/workspaces/qsvenc-831` (r4604, gcc 13.3).

### Established Patterns
- Surface pools are per pipeline edge (`PipelineTaskSurfaces`), reuse gated solely by `mfxFrameSurface1::Data.Locked == 0`.
- Downstream tasks receive `PipelineTaskOutputSurf` carrying a syncpoint; `SyncOperation` is invoked lazily in `PipelineTaskOutput::waitsync`, not necessarily before the surface becomes an input to the next MFX component.
- `vaSyncSurface` is used only in the VA allocator copy path (`qsv_allocator_va.cpp:230,258`), not on the main decode→VPP→encode path.

### Integration Points
- Trace hooks: `getFreeSurf`, task output push/pop, `waitsync`, MFX `DecodeFrameAsync` / `RunFrameVPPAsync` / `EncodeFrameAsync` call sites.
- Fix likely lands in `qsv_pipeline_ctrl.h` / `qsv_pipeline.cpp` / `qsv_allocator_va.cpp` (QSV-specific — no common-file impact expected).

</code_context>

## Specific Ideas

- Phase 2 found the corrupt frame is NOT a clean copy of another concurrent session's frame (best cross PSNR 10.5–18.6 dB) → the "cross-session leak" framing may be wrong; concurrency may only perturb timing that exposes an intra-session sync/reuse race. D-01 tests this cheaply.
- ffmpeg clean on the same kernel is the key contradiction to the earlier "kernel-only" verdict — the comparison is the lever.
