Walk the coarse-lever ladder (D-05) with the diagnostic binary from 02.1-02 — one boundary per screen — so every examined hypothesis is confirmed or refuted by harness numbers, then hand the operator a data-backed path decision (fix / negative close / extra budget).

Ordering rule from 02.1-02 X4 outcome (read it from EVIDENCE first):
- GATE PASS + LOCALISED to an edge -> screen the toggle for that edge first (VPP->ENC: X5, DEC->VPP: X6, reuse/pool: X7b then X7a), then the rest.
- GATE PASS + INCONCLUSIVE -> order X5, X6, X7b, X7a (D-05 bisection, one boundary at a time).
- GATE FAIL (instrumentation masked the race) -> run every screen with tracing OFF (no QSVENC_TRACE_ENABLE in cand.env), and before the first toggle screen run a toggles-off, trace-off positive control `T2-pc` (cand_screen MAX 20) that must be REJECTED; if T2-pc is NOT rejected, the diag binary itself perturbs timing — stop and take that to the checkpoint (Task 4) as evidence for a timing race.
- X3 (02.1-01) ESCALATED -> any toggle cure must be labelled "sync OR timing" until X8/H7 disambiguates.
