### `QSVPipeline/qsv_pipeline_ctrl.h` — FIX / coarse toggle X5: consumer-side wait before `EncodeFrameAsync` (fix commit; env-gated variant in diag commit)

**Analog:** the existing `waitsync` usage. Three precedents of calling `waitsync()` on a `PipelineTaskOutput` from the CPU thread:

1. Generic producer-side loop, `PipelineTask::getOutput` (`:597-612`):
```cpp

        }
```
2. VPP flush path, `:2215`: `sts = output->waitsync();`
3. CheckPTS, `:1559`: `out->waitsync();`

**Where to insert the fix** — `PipelineTaskMFXEncode::sendFrame` top, immediately after the type check (`:2605-2610`):
```cpp
    virtual RGY_ERR sendFrame(std::unique_ptr<PipelineTaskOutput>& frame) override {
        if (m_stopwatch) m_stopwatch->set(0);
        if (frame && frame->type() != PipelineTaskOutputType::SURFACE) {
            PrintMes(RGY_LOG_ERROR, _T("Invalid frame type.\n"));
            return RGY_ERR_UNSUPPORTED;
        }
        // <-- fix: if (frame) { frame->waitsync(); }   // no-op when syncpoint already null
```
Minimal always-on form (RESEARCH §Minimal fix candidate; D-12 = no option):
```cpp
if (frame) { frame->waitsync(); }   // wait for the producer's (VPP) syncpoint before EncodeFrameAsync
```
Alternative variant to compare for fps (D-07): `requireSync` (`:620-622`, `return isMFXTask(m_type) != isMFXTask(nextTaskType);`) additionally true for `MFXVPP -> MFXENCODE`. NOTE the two `requireSync` definitions: the member at `:620` (task-type based) and the lambda at `qsv_pipeline.cpp:5985-5995` (position based, has the latent `size_t prevtask >= 0` bug — do NOT touch, RESEARCH pitfall 9).

**Pitfalls to copy from RESEARCH/code:**
- `PipelineTaskTrim` builds outputs with NULL `m_mfxSession` (`qsv_pipeline_ctrl.h:2026,2062`): `waitsync()` on a live syncpoint there would dereference null. Sync at the consumer (encoder) or producer `getOutput`, never through Trim.
- `waitsync` ignores/clears syncpoint even on `MFX_WRN_IN_EXECUTION` (`:353`), and `getOutput` ignores the return (`:604`). Do not build correctness on the return value.
- `frame` is `nullptr` on the encoder flush call (`sendFrame(flushFrame)` `:2701`) — the `if (frame)` guard is mandatory.

**Env-gated diag variants (diag commit only, default OFF, env read once):** copy the rtgmc idiom:
`QSVENC_DIAG_SYNC_ENC=1` (above wait), `QSVENC_DIAG_SYNC_DEC=1` (`m_outQeueue.back()->waitsync()` after `:1300`), `QSVENC_DIAG_RR=1` (round-robin start index in `getFreeSurf` `:282-289`; keep a `size_t m_rrNext` member next to `m_surfaces`, scan `(m_rrNext + k) % n`), `QSVENC_DIAG_POOL_EXTRA=<n>`, `QSVENC_DIAG_ENC_ASYNC=<n>`.
