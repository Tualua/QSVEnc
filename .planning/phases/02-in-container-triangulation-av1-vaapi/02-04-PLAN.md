<objective>
Add the content-origin cross-match (D-09/D-10): a search that, for any corrupt frame, finds its best pixel match among the OTHER two concurrently-running scenes' same-iteration frames — upgrading the finding from "PSNR-drop symptom" to "confirmed cross-session content swap." Apply it to the existing Phase-1 qsvencc corrupt frames (closing the mechanism note Phase 1 explicitly deferred) and wire it into the av1_vaapi corrupt path.

Purpose: Roadmap SC#2 and CONTEXT D-09/D-10 want the triangulation to establish the mechanism, not just the symptom. The Phase-1 summary.txt "Mechanism-vs-symptom NOTE" explicitly deferred cross-session content-origin confirmation to Phase 2. This plan closes that thread using only the Phase-1-proven psnr_of primitive (OpenCL-free, <30 dB threshold) wrapped in a new best-match search loop — no new methodology.

COST REALITY (corrects RESEARCH.md's "well under 1000 ffmpeg invocations", which is WRONG): the full historical qsvencc scan is ~17 corrupt frames x 2 other scenes x ~450-470 candidate frames x 2 ffmpeg calls each ≈ **8,000-16,000 ffmpeg invocations, ~2-4 hours wall-clock**. It is GPU-free (decode + PSNR only, no Arc contention) but it is NOT a trivial-cost verify-block step. This plan therefore SPLITS the work: Task 1 builds the code and proves it on a tiny smoke subset (fast, autonomous-verifiable); Task 2 runs the full historical scan as a long operator batch (verify checks the produced artifact, never re-runs the scan inside a short timeout); Task 3 wires the same function into the av1_vaapi path.

Output: content_cross_match() + cmd_cross_match_qsvencc subcommand + av1_vaapi corrupt-path wiring in harness.sh; on-disk crossmatch_qsvencc.txt confirming (or refuting) cross-session content origin for the Phase-1 corrupt frames, with an explicit threshold-band verdict.
</objective>
